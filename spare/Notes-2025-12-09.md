# BAUX Project Priorities and Next Steps - 2025-12-09

## Vision Recap
BAUX is a minimalist swiss army knife for makers: USB boot to connect to your Neovim IDE in the BAUX-MESH in 5 seconds from ANY system, getting you to your code with the best vi/tools available on any broken embedded/SBC/server hardware for fast recovery and development.

## Current Implementation Status (from ports/baux/ code review)
- **Session Persistence & IDE Access**: 80% complete (tmux resurrect/continuum, Neovim configs).
- **Installation & Setup**: 90% complete (install.sh, baux script).
- **Keybindings & UX**: 85% complete (consistent tmux/Neovim mappings).
- **Minimalism**: 70% complete (core scripts simple, but Neovim configs bloated).
- **BAUX-MESH**: 20% complete (placeholders in baux script, no actual networking).
- **5-Second Boot**: 10% complete (no optimizations).
- **Recovery Tools**: 30% complete (session resurrection only).
- **Any System Support**: 40% complete (FreeBSD-specific).

## Prioritized Next Steps

### High Priority
1. **Implement BAUX-MESH with Headscale** (User-suggested next step)
   - Add Headscale client integration to baux script for mesh discovery and peer-to-peer session sync.
   - Enables "connect from ANY system" via distributed networking.
   - Rationale: Core to vision's "swiss army knife" for cross-device continuity.

2. **Add Recovery Tools**
   - Create scripts for USB imaging (dd wrappers), dead drive mounting, SBC flashing.
   - Integrate into baux sub-commands (e.g., baux recover).
   - Rationale: Supports "recovery on broken systems" and immediate user value.

### Medium Priority
3. **Optimize Boot Time**
   - Profile tmux/Neovim startup, add preloading/caching.
   - Target measurable <5s boot.
   - Rationale: Critical for "5 seconds" usability.

4. **Dual Neovim Configs**
   - from small to bloat config 2 version with fall back saftey

### Low Priority
5. **Cross-Platform Support**
   - Add OS detection, alternative commands (sudo vs. doas).
   - Enable Linux/macOS/Windows usage.
   - Rationale: Expands "any system" adoption.

## Tradeoffs and Considerations
- **Headscale vs. Recovery**: Headscale enables distributed features but may delay immediate tools. Recovery provides quick wins but less visionary impact.
- **Minimalism Balance**: Simplifying configs risks losing features; prioritize core IDE needs.
- **Testing**: Add integration tests for new components to prevent regressions.

## Action Items for Tomorrow
- Start with Headscale integration in baux script.
- Prototype a basic recovery tool (e.g., USB imaging script).
- Review and trim Neovim configs.

This roadmap gets BAUX to 80-90% vision completion. Adjust based on progress or new insights.
